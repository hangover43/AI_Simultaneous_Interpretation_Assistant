# PRD：AI 同声传译浏览器插件

## 背景

用户经常在网页或电脑浏览器中观看外语视频，例如技术演讲、课程、会议录播和产品发布会。传统字幕工具要么依赖视频自带字幕，要么不能结合上下文修正前文翻译。这个项目的重点是做一个本地实时翻译插件，并突出“翻译后可修正”的能力。

## 产品目标

- 用户打开任意网页视频后，可以在当前网页看到实时翻译字幕。
- 用户可以在右侧面板看到完整历史记录，格式为“原文 + 译文”。
- 如果后端基于上下文修正了前文翻译，历史记录中的对应项保持高亮。
- 首版优先本地运行，使用 Java 后端、whisper.cpp 和 Ollama。

## 用户场景

1. 用户打开 YouTube、课程网站或其他网页视频。
2. 用户点击浏览器插件图标，打开右侧面板。
3. 用户输入或保留默认 topic。
4. 用户点击开始。
5. 插件捕获当前标签页音频并发送到本地后端。
6. 页面底部显示实时翻译字幕。
7. 右侧面板持续记录原文和译文。
8. 如果系统修正前文，历史记录中对应条目高亮。

## 功能范围

### 必做

- Manifest V3 浏览器插件。
- 当前标签页音频捕获。
- WebSocket 音频分片上传。
- Java Spring Boot 后端。
- whisper.cpp ASR。
- Ollama 本地翻译。
- 网页字幕 overlay。
- 右侧历史翻译面板。
- 修正结果高亮。
- mock 演示模式。

### 暂不做

- 移动端。
- 云端账号系统。
- 视频文件播放器。
- 字幕文件导出。
- 多用户协作。
- 复杂术语表编辑 UI。

## 交互要求

### 侧边栏

只保留必要信息：

```text
主题输入
开始 / 停止 / 清空
后端模型状态
历史翻译列表
```

历史记录格式：

```text
原文
...
译文
...
```

未修正记录正常显示；修正过的记录使用高亮背景，并一直保持高亮。

### 网页字幕

- 显示在页面底部。
- 不遮挡整个页面。
- 只展示最新译文。
- 修正结果不回放到弹幕，只更新历史记录。

## 技术亮点

### 实时性

使用 5 秒音频分片，先保证稳定闭环。后续可降到 3 秒，或引入流式 ASR 降低延迟。

### 修正能力

实时字幕优先低延迟；历史面板承担修正展示。这样即使视频已经播放过去，用户仍然能在右侧看到更准确的最终译文。

### 本地隐私

音频、转写和翻译全部在本机处理，不依赖云端 API。

## 验收标准

- 后端 `GET /api/health` 返回 `ok`。
- 后端 `GET /api/ai/provider` 显示 `ollama / qwen2.5:3b`。
- 插件面板可以正常打开，无乱码和脚本错误。
- 点击开始后可以捕获当前标签页音频。
- 真实 webm 音频可以完成 `ASR -> 翻译 -> WebSocket 返回`。
- 网页底部能显示翻译字幕。
- 右侧面板能显示历史记录。
- 修正消息能让对应历史记录高亮。
